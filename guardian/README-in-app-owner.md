# Native Guardian owner access
The owner panel uses the existing Compose theme and a JSON-only HTTPS interface. No WebView, external browser, provider branding or raw network errors are displayed. Owner email and separate password remain in server configuration. The login token is kept only in memory, expires after 30 minutes, and is invalidated on explicit sign-out or replacement login. Closing the activity clears local credentials; the server session expires automatically. Password fields are not saved and screenshots are blocked. Existing activation and player behavior are unchanged. The staging host remains discoverable through network inspection. A native Android build and real-device login, invitation, cancellation, revocation and playback tests are required before production release.


Recovery candidate: owner access is available from unlocked Settings; an optional Android 11+ screen-lock authenticated AndroidKeyStore AES-GCM cache keeps only the native session token in no-backup storage. Resume requires device credential and server validation. Explicit sign-out and server 401 clear the cache; the existing 30-minute server session and process-restart invalidation still apply. No passwords are persisted, no entitlement bypass, no screenshot-policy relaxation. A separate durable, revocable server session design is required to survive hosting sleep/restarts. Activation now serializes device exchanges, allows longer first-request read timeout, and separates transient errors from denial. Server challenge recovery returns the existing same-action nonce without extending expiry and consumes only valid proofs. Do not deploy without backend and Android regression tests.
