# Hosted Guardian owner staging (not deployed)
Use a separate Render web service, never the public activation API. Start with:
`gunicorn --config guardian/deploy/gunicorn.conf.py 'guardian.managed_owner:create_app()'`
Use the same dedicated Guardian database, restricted runtime database role and existing pepper through a secure secret manager or the Render dashboard. Do not put secrets in Git, chat, logs, or the APK. No signing private key is needed. Set VOID_GUARDIAN_OWNER_HOST to the exact assigned HTTPS hostname and VOID_GUARDIAN_OWNER_PASSWORD_SHA256 to the SHA-256 hex digest of a locally generated high-entropy password (at least 32 random bytes). Username is owner. Use a password manager. This is an interim single-owner HTTPS Basic-auth staging console, not a production identity system. Keep access private; add an identity-aware proxy/MFA before production. Application audit logs contain action and outcome only, not durable database audit history. Existing invitation expiry is enforced on store operations; no periodic hosted cleanup job is provided yet. A successful redemption is lifetime unless revoked. Offline clients cannot observe revocation until an online check. Do not ship the APK until production signing material, full owner login and device tests are verified.
