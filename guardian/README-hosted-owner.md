# Hosted Guardian owner staging (not deployed)
Separate Render service only, not the public activation API. Start: `gunicorn --config guardian/deploy/gunicorn.conf.py 'guardian.managed_owner:create_app()'`. Use one worker (sessions and login budgets are in memory). Set VOID_GUARDIAN_BIND to 0.0.0.0:10000, VOID_GUARDIAN_OWNER_HOST to its assigned HTTPS hostname, and copy the existing dedicated Guardian database URL and pepper securely from the activation service. No signing private key is needed. Run `python -m guardian.owner_password_setup` on a trusted machine to configure the single Gmail address and separate Guardian password. Never use the Google account password. Set only the resulting salt and scrypt verifier in the private environment; never commit them or share in chat. There is no registration, email ownership verification, Google OAuth, password reset or multi-owner support. One active 30-minute session, revoked on new login, logout or process restart. Five login attempts per minute globally; a busy password-hashing worker rejects concurrent attempts. Add identity-aware MFA and durable audit before production. Audit logs contain action/outcome only. Expiry is enforced on store operations; scheduled cleanup not yet implemented. Lifetime access is revoked on next successful online check.
